# Kits specify a sandbox's contents and requests; AX manages tasks

These answer **different questions**:

- **Kit:** “What software should this sandbox contain, and what network, credentials, or files does it request?” For example, combine a Bash workload with a GitHub CLI mixin that asks for GitHub access. The Kit is an OCI image carrying those declarations; Docker's `sbx` runtime creates the microVM and decides what to grant ([Kit spec](https://github.com/docker/sandbox-kit-spec/blob/5fabb0a260db4fded6c2f2da76e89b7582c9b536/docs/spec/SPEC-v3.md#1-overview), [official example](https://github.com/docker/sandbox-kit-spec/blob/5fabb0a260db4fded6c2f2da76e89b7582c9b536/README.md#how-to-get-started), [sandbox security](https://docs.docker.com/ai/sandboxes/security/)).
- **AX:** “How do I submit, observe, suspend, resume, and delete many isolated tasks in a cluster?” Its `Task` names an image and command, `Workspace` specifies setup, and controllers reconcile task state through Redis and Agent Substrate actors. Substrate provides the isolation; AX is the control plane, **not** a portable permission descriptor inside the image ([AX concepts](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/concepts.md), [design](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/DESIGN.md#architecture)).

**They do not compose automatically.** AX expects a task image with its runner contract and does not document interpreting a Kit's permission annotation; running the image as an ordinary image would not enforce those Kit requests ([AX runner](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/runner.md#how-a-runner-is-launched), [Kit spec](https://github.com/docker/sandbox-kit-spec/blob/5fabb0a260db4fded6c2f2da76e89b7582c9b536/docs/spec/SPEC-v3.md#1-overview)). AX's suspend/resume preserves workspace files but starts a new process tree, not a paused agent's memory ([runner contract](https://github.com/google/ax/blob/e09ed1bc5463ad4b5ca88f755a6e1e2005b3c7b7/docs/runner.md#how-a-runner-is-launched)).
