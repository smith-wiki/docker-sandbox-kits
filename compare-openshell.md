# Yes—but OpenShell competes with `sbx`, not with a Kit alone

**At the runtime layer, yes.** NVIDIA OpenShell competes most directly with Docker Sandboxes/`sbx`: both launch agent workloads, isolate them, and enforce access. A Docker **Kit alone** is instead a package/specification: one OCI image whose manifest annotation carries typed capability requests. A supporting runtime interprets those requests; an engine that does not read the annotation treats it as an ordinary image ([Kit v3 overview](https://github.com/docker/sandbox-kit-spec/blob/5fabb0a260db4fded6c2f2da76e89b7582c9b536/docs/spec/SPEC-v3.md#1-overview), [`sbx` Kit guide](https://docs.docker.com/ai/sandboxes/customize/use-kits/)).

OpenShell is a runtime plus control plane. It launches agents from OCI images, and its built-in compute drivers cover Docker, rootless Podman, Kubernetes, and MicroVM; local deployments use Docker, Podman, or a VM, while remote deployments use Kubernetes ([OCI image example](https://github.com/NVIDIA/OpenShell#create-a-sandbox), [drivers](https://docs.nvidia.com/openshell/reference/sandbox-compute-drivers), [deployment models](https://docs.nvidia.com/openshell/about/how-it-works#deployment-models)). The gateway owns desired state and policy revisions; a sandbox-local supervisor enforces process, filesystem, network, and credential rules ([architecture](https://docs.nvidia.com/openshell/about/how-it-works#gateways-and-sandboxes)).

The permission models overlap but travel differently. Kits embed versioned requests—network, credentials, volumes, lifecycle, and more—in the OCI manifest. OpenShell takes YAML policy supplied at creation or, for its community base image, baked into the image; its gateway delivers policy and its supervisor enforces it ([Kit capabilities](https://github.com/docker/sandbox-kit-spec/blob/5fabb0a260db4fded6c2f2da76e89b7582c9b536/docs/spec/SPEC-v3.md#7-capabilities), [custom policy](https://docs.nvidia.com/openshell/sandboxes/policies#apply-a-custom-policy), [bundled default](https://docs.nvidia.com/openshell/reference/default-policy)). Filesystem, Landlock, and process policy are fixed at creation; network rules can change without recreating the sandbox ([policy updates](https://docs.nvidia.com/openshell/sandboxes/policies#policy-structure)). OpenShell's documented image path does **not** say it reads Docker's Kit annotation: do not assume Kit requests activate there ([image path](https://docs.nvidia.com/openshell/sandboxes/manage-sandboxes#custom-containers)).

**Choose by layer:** compare OpenShell with `sbx` on isolation, deployment, policy depth, credentials, and operations; compare a Kit with other portable environment/access descriptors.
